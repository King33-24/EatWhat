# 认知棱镜 (EatWhat)
面墙而立，破壁而观。
## 一. 简介
一款不推送、不说教、不替你思考的认知健康智能体。它通过审视你的数字足迹，帮你看见信息茧房之外的世界，并重新掌握深度思考的主动权。它从不替你做决定，只做三件事——呈现、追问、邀请。

## 二. 功能清单
### 1. 认知体检报告
智能体通过读取用户在浏览兴趣内容时网页传回的数据，分析用户在主流平台（B站网页版）的浏览/收藏/互动记录，生成一份私密的“认知体检报告”。  
若用户要求生成，则立刻生成，若用户未关注，则以周为单位更新。  
以查看报告时一周以内的数据进行分析  
（累计的分析和观点变化的报告我还没想好怎么搞要不要搞，可以放在精进环节？）
报告包含：
1. 兴趣地图：用户本周关注最多的5个话题域是什么。

2. 观点倾向光谱：用户在几个关键争议议题上（如AI发展、教育内卷、消费主义等），目前接收到的内容落在观点的哪个区间。

3. 思维盲区快照：列出1-2个被系统性地忽略的视角。比如，“你这周看了8个关于‘数字游民’的视频，但没有任何内容讨论这种生活方式的可持续性风险。”

4. 情绪共鸣模式：用户点赞/收藏的高频内容，勾起了哪种共同情绪？是“爽”、“焦虑共鸣”还是“希望”？

### 2. 平行书架
基于前文中的体检报告，智能体为用户每个“思维盲区”，各匹配 2-3个高质量的对立/中立视角内容源（公众号、文章、视频、播客单集）。  
设计原则：不是主动推送，无任何红点或弹窗提醒。用户需要主动点进这个标签，才能看到。避免“被打扰”和“被教育”的感觉，让用户掌握完全的主动权。
1. 信息源严格筛选：  
只选择在该视角下被广泛认可、论述理性、非煽动情绪的创作者或媒体。  
它一定是“值得被倾听的另一种声音”，而不是边缘极端言论。  
智能体会标注：“这篇的作者是一位长期研究XXX的学者，他的核心关切是YYY。这一观点在AAA群体中较为普遍，因为ZZZ。”
2. 差异对比卡片：  
每篇推荐旁，智能体生成一张卡片，简洁说明：  
它和用户常看的内容，在最根本的假设上有什么不同。  
为什么一些理性的人会持有这个观点。  
用户可以只花30秒或一分钟看它的核心论证框架，再决定是否深读。
3. 苏格拉底式的追问：  
用户可在此区域与智能体进行更进一步的探讨，在讨论中思考自己的观点与盲区。也可向智能体提出建议，比如对智能体筛选的内容或生成的报告有异议，智能体相应做出调整。

### 3. 他人之眼
用户可以选择一个预设的“身份镜像”（如：小镇退休教师、一线城市外卖员、大厂HR、备考的高三学生），智能体调用该群体典型的平台数据画像（脱敏模拟），为你生成一个非真实的首页信息流预览。
1. 选择身份后：  
让用户“刷5分钟另一个人的世界”——用户会看到算法推荐给他的是什么视频、什么文章、什么广告。用“角色扮演”的游戏感，帮助用户观点切换与深度共情。
2. 引导记录：  
智能体会在体验后引导你记录：“你们最意外的共鸣点是什么？最深刻的差异在哪里？”
用户不需要认同，甚至会更坚定自己的想法，但会理解为什么另一些人会那么想。理解不等于认同，这正是对抗极化的关键。

### 4. 沧海遗珠（逆向推荐）
基于用户真正深度消费的内容（完整看完、反复观看、主动搜索），智能体在全网寻回那些被算法时间线埋没的经典（长文、纪录片等）。推送时，它会附上一封“小信”：“这篇2019年的长文，和你上周痴迷的那个系列，在XXX问题上的探讨一脉相承，但走得更远。我认为你可能会喜欢它带来的新困惑。”

### 5. 冷静期盒子
当用户特别想点开一个自己潜意识里知道是“低质但上瘾”的内容时，可以分享给智能体，它帮用户存到一个“7天后解锁”的盒子里。7天后，如果用户还想看，它就在那里，也可能用户根本想不起来了。

## 三. 技术栈
开发环境：VMware Player + Ubuntu 24.04  
浏览器：Google Chrome for Linux  
监测网站：B站网页版  
智能体核心：OpenClaw  
大模型 API：Gemini 2.5pro    
后端 API：FastAPI + Uvicorn  
定时任务：APScheduler  
数据库：SQLite  
前端图表：Chart.js (CDN)  
协作工具：GitHub + VS Code  
开发工具：VS Code  


本机（Windows）  
└── VMware窗口（只看不用）  
    └── 虚拟机 Ubuntu 24.04  
        ├── Chrome浏览器 ← 在这里刷B站  
        │   └── 认知采集扩展（读取页面→发localhost:8000）  
        ├── FastAPI后端（localhost:8000）  
        │   ├── 接收数据 → SQLite  
        │   ├── 前端静态文件（localhost:8000/）  
        │   └── 查询接口  
        ├── OpenClaw分析引擎  
        │   └── 读取SQLite → 调用Gemini → 生成报告  
        └── VS Code（写代码）
